based on our chat history, i want to make readme file for my circle ci implementation with what problems i face how i solved it and what was the impact of the solution, here are some key highlights of the project:
1.modularized shared-config.yml into different files under shared folder and then pack them together at run time using circleci-cli tools config pack
2.creating separate folders/files for separate jobs and workflows,
3.running the pipeline using circleci orbs  using alpine docker image for faster pipeline times instead of base circle docker image which takes time to download reduced size of download from 189mb to 30mb including(base alpine image + installing sudo, bash,git,curl,wget,jq)

5.triggering different pipeline within same branch ,another branch in the same project, branches inside different project using api, by first generating pipeline from config.yml file which has setup:true thereby generating config_api.yml file which has curl api request to trigger pipeline in another job inside branch or different branch or different project,
benefit:
1.easier maintenance of the jobs due to separation of concerns as their is now not a requirement of monolithic file having all the jobs and workflows mentioned in it but rather jobs can be modularized and pack at the run time
2.can trigger pipeline into any branch,any project from any branch and conditionally run any projects
3.can run the orb specific job in any shell environment and produce same output 
4.faster running pipeline using lightweight alpine docker images

best practice:
if dependent job has a filter, then the dependency job must also have the same filter otherwise workflow won't be generated if parent job
save cache of yarn packages/dependancy to persist in the pipeline and the different jobs can use cache instead of installing in every workflow run
yarn install --frozen-lockfile to lock dependency install to the version mentioned in the package json and strict adherence to yarn.lock file
if jobs depend on the install job then use persist to workspace in install job and attach to workspace in the dependant jobs for faster running of the pipeline
if jobs are running independently then save and restore cache of yarn packages for faster running of the pipeline
always use lightweight docker images whenever possible for faster running pipelines
when running the script i.e. .sh file make it executable
save and access the variables inside the environment of the ci tool for security purposes
access context and environment variables to retrieve information about branch,tags, current commit, before commit, security token
